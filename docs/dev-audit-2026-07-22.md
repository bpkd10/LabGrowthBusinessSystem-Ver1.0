# DEV Audit: Business Growth CRM

วันที่ตรวจ: 22 กรกฎาคม 2026

## สถานะการใช้งานหลัก

| ส่วนระบบ | สถานะ | หลักฐานการตรวจ |
|---|---|---|
| Business Profile และ Dashboard | ใช้งานได้ | เปลี่ยน Business Mode แล้ว KPI, Journey และคำแนะนำเปลี่ยนตาม |
| Customer และ CRM | ใช้งานได้ | เพิ่ม แก้ไข ลบ และสร้าง Lead ที่สัมพันธ์กับ Customer |
| Package / Offer | ใช้งานได้ | สร้างและแก้ชื่อ หมวดธุรกิจ ราคา ต้นทุน รายละเอียด เหตุผลแนะนำ และ Pipeline Stage |
| Package relation | ใช้งานได้ | แก้ Package แล้ว Customer selector, Deal selector, CRM และ AI payload ใช้ข้อมูลใหม่ |
| Deal และ Pipeline | ใช้งานได้ | เชื่อม Customer และ Package ด้วย ID โดยชื่อดีลเฉพาะของผู้ใช้ไม่ถูกเขียนทับ |
| Task | ใช้งานได้ | สร้าง แก้ไข เปลี่ยนสถานะ และลบ |
| Import | ใช้งานได้ | JSON, CSV, CVS, TSV, XLS, XLSX, MD, TXT, DOC และ DOCX พร้อม Preview และ Mapping |
| Export และ Set Zero | ใช้งานได้ | Export JSON และขั้นยืนยัน Set Zero 3 ขั้น |
| AI Analysis | ใช้งานได้เมื่อ Server มี API key | ส่งเฉพาะข้อมูลธุรกิจที่อยู่ในระบบไปวิเคราะห์ |

## สิ่งที่แก้ในรอบนี้

- เพิ่ม Import Engine แยกจาก UI เพื่อให้ทดสอบ parser และ mapping ได้โดยตรง
- จำกัดไฟล์ไม่เกิน 10 MB และบังคับ Preview ก่อนเขียนลงระบบ
- ตรวจประเภทข้อมูลอัตโนมัติ หรือให้ผู้ใช้เลือก Customer, Package, Deal และ Task เอง
- นำเข้าลูกค้าแล้วสร้าง Lead ที่อ้างอิง Customer ID เดียวกัน
- ป้องกันข้อมูลซ้ำเมื่อ Import ไฟล์เดิม โดยใช้เบอร์โทรลูกค้า ชื่อ Package ชื่อดีล และคีย์ของ Task
- อัปเดต SheetJS เป็น 0.20.3 จากแหล่งทางการ และ Mammoth เป็น 1.12.0; ผลติดตั้งล่าสุดรายงาน 0 vulnerabilities
- ขยาย Package ให้ Customize และ Edit บริบทธุรกิจ คำอธิบาย และเหตุผลแนะนำได้
- เพิ่มชุดข้อมูลจำลอง 4 ธุรกิจใน `scripts/fixtures/business-samples` ครอบคลุมคอร์ส Uncle Tung AI, ร้านอาหารและ Bakery, CARLab+ และร้านนวด พร้อมไฟล์ `.cvs`, `.md`, `.doc` และ `.txt`
- เพิ่ม `check:fixtures` ให้ทดสอบการอ่านไฟล์จริงทั้ง 4 ธุรกิจ และตรวจความสัมพันธ์ Product–Customer–Deal–Task ก่อนนำเข้าระบบ
- รองรับ `.cvs` เป็น alias ของ CSV และปรับตัวอ่าน `.doc` ข้อความ UTF-8 ภาษาไทยให้ตรวจ Preview ได้ถูกต้องขึ้น

## ข้อจำกัดที่ต้องรู้

1. ไฟล์ `.doc` รุ่นเก่าเป็น Binary format และไม่มีโครงสร้างตารางมาตรฐานใน browser ระบบจึงดึงข้อความพื้นฐานและเตือนให้ตรวจ Preview ทุกครั้ง หากไฟล์ซับซ้อนควร Save As เป็น `.docx` ก่อน ชุดจำลอง `.doc` เป็น UTF-8 key-value เพื่อทดสอบได้สม่ำเสมอ
2. Import ปัจจุบันใช้ชื่อหัวคอลัมน์ภาษาไทย/อังกฤษที่พบบ่อย หากองค์กรใช้ชื่อเฉพาะมาก ควรเพิ่มหน้าจอ Column Mapping แบบลากเลือกในรุ่นถัดไป
3. ระบบเก็บข้อมูลใน `localStorage` เหมาะกับ Demo, Workshop และผู้ใช้คนเดียวบนเครื่องเดียว ยังไม่เหมาะกับหลาย User, สิทธิ์ตาม Role, Audit Log หรือข้อมูลลูกค้าจริงที่ต้อง Sync ข้ามอุปกรณ์
4. ข้อมูลที่ AI วิเคราะห์เป็น Snapshot ณ เวลาส่งคำถาม หากต้องการประวัติผลวิเคราะห์และเปรียบเทียบรายสัปดาห์ ต้องเพิ่มฐานข้อมูลและ Analysis History

## ลำดับพัฒนาต่อที่แนะนำ

1. ย้าย State ไป Backend database พร้อม Login, Role permission, Backup และ Audit Log
2. เพิ่ม Column Mapping UI และ Import report ที่ดาวน์โหลดแถวผิดพลาดกลับไปแก้ได้
3. เพิ่ม Validation Rule ตามธุรกิจ เช่น เบอร์โทรซ้ำ เลขผู้เสียภาษี SKU และรหัสสาขา
4. เพิ่ม Test Browser แบบอัตโนมัติใน CI สำหรับ Import, Package relation, Set Zero และ AI error state
5. เพิ่ม Data retention และ PDPA consent ก่อนนำข้อมูลลูกค้าจริงมาใช้
